# Registre des écarts voulus du golden master

Chaque ligne décrit un scénario du golden master du legacy que la nouvelle application **ne reproduit pas à l'identique**, par décision. Un écart inscrit ici n'est pas une régression au rejeu final (NFR-PAR-01). Les décisions de rejeu correspondantes sont dans `replay-mapping.json`, à la racine du dépôt.

*Décisions du 2026-10-05, prises à l'étape G2 (`corpus-bmad-golden-master`).*

| Scénario | Comportement de l'application d'origine | Comportement de la nouvelle application | Raison | Exigence ou test qui couvre le cas |
|---|---|---|---|---|
| **SC-001-02** : accès sans session à une page protégée | `GET /dashboard.xhtml` sans session → **302**, redirection vers `login.xhtml` | `GET /api/coeur-bancaire/tableau-de-bord` sans jeton → **401**. C'est le routeur du front qui ramène vers `/login`. | La nouvelle application est une SPA dont le jeton est en stockage local : le serveur ne peut pas rediriger une requête d'API (AD-16, AD-17). Le scénario reste dans le golden master, adapté (`map`). | Golden master SC-001-02 (`map`, statut 401) ; FR-001-02 et FR-030-01 (redirection vers la connexion, faite par le front) ; AD-17 ; tests d'intégration de AD-16 (requête sans jeton → 401) |
| **SC-017-01** : téléchargement d'un PDF sans session | `GET /docs/download?type=RIB&accountId=1` sans session → **302** vers la connexion | `GET /api/documents/telechargement?type=RIB&compteId=1` sans jeton → **401** | Même raison que SC-001-02 : pas de redirection serveur pour l'authentification (AD-17). Le scénario reste dans le golden master, adapté (`map`). | Golden master SC-017-01 (`map`, statut 401) ; FR-017-01 (session obligatoire pour télécharger) ; AD-17 ; tests d'intégration du service documents (requête sans jeton → 401) |
| **SC-001-03** : identifiants incorrects | `POST /login.xhtml` (formulaire) → **200**, page de connexion contenant « Identifiants incorrects » (comparaison : statut + texte dans le corps) | `POST /api/identite-clients/connexion` (JSON `identifiant`, `motDePasse`) → **401** avec le corps `{"message":"Identifiants incorrects"}` | La connexion passe par l'API du service identité et clients. Le format d'erreur `{message}` est une décision d'architecture (AD-17). Le message affiché reste « Identifiants incorrects ». Le scénario reste dans le golden master, adapté (`map`, statut + extrait JSON). | Golden master SC-001-03 (`map`, 401 + `json_subset`) ; FR-001-06 (échec d'authentification, message « Identifiants incorrects ») ; AD-17 |
| **SC-010-02** : authentification refusée par le service d'IA du chat | Le chat affiche le code technique « (HTTP 401) » | Le chat annonce que le conseiller est temporairement indisponible, sans code technique | Le scénario figeait le bug BUG-038, que le métier a décidé de corriger. **Exclu du golden master** (`drop` prérempli, motif « corrigé dans le forward »). La règle **RG-010-007** sort donc du golden master. | Test de la nouvelle application prouvant FR-010-09 (correction de BUG-038), avec l'adaptateur simulé d'Azure OpenAI en mode « refus 401/403 » ; NFR-PAR-02 (chaque bug corrigé est couvert par un test) |
